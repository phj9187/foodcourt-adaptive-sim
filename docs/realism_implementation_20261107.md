# 대학 푸드코트 고객 행동과 도입 효과 검증 수정

2026-11-07. [최종 현실성 연구](realism_final_research_20261106_ko.md)의 고객 행동과 비교 실험 권고를 반영했습니다. 수치와 분포는 합성 가정입니다.

## 한 운영기간에 누가 방문하는가

한 푸드코트에 다른 예산·취향·시간 여유·알레르기·제외 메뉴 조건을 가진 고객이 섞여 방문합니다. 낮은 예산과 높은 가격 민감도, 짧은 여유와 높은 대기 민감도가 연결되도록 합성 공동분포를 사용합니다. 고객은 취향·가격·대기의 5단계 입력을 제공하며, 취향 입력에는 오차를 넣습니다. 예산·알레르기·명시적 제외·재고는 필수 제약으로 유지합니다.

하루 안에 비교형, 충분히 마음에 들면 탐색을 끝내는 유형, 가격·시간·취향 중 하나를 우선하는 유형이 섞입니다. 운영기간마다 어느 유형이 60%로 우세한지 바꾸고 나머지는 각 20%로 섞습니다. 개인의 유형은 그 기간에 유지됩니다. 같은 평가함수의 PPO를 여러 시설과 고객 구성에서 학습합니다. 평가함수의 계수는 고객 생성과 행동에 들어가지 않습니다.

## 고객의 방문에서 다음 방문까지

1. 시설의 조리능력과 독립적으로 잠재 방문 기회를 생성합니다. 기존 용량 연동 수요도 부하 실험용으로 선택할 수 있습니다. 가격 변경 실험에서는 생성 때 정한 예산 범위가 고정됩니다.
2. 일부 잠재 방문 기회에는 같은 고객 ID가 다시 나타납니다. 고객의 경험을 취향·가격·대기 체감치의 개인별 가중 평균으로 가정하고, 기억에 따라 방문 확률과 이전에 먹은 음식 종류의 선호를 갱신합니다. 이 경험 규칙은 실측 만족도나 학습용 평가점수와 별개입니다.
3. 고객이 방문하면 줄에 들어갈지 결정하고, 기다리다 떠날 수도 있습니다. 화면의 위치와 사전 인기가 메뉴 발견에 영향을 주며, 추천을 본 고객만 추천 메뉴를 탐색 후보에 올립니다. 메뉴 수에 비례한 불이익은 없습니다.
4. 고객이 주문하지 않거나, 대기 예상이 시간 여유를 넘거나, 결제 시점에 품절될 수 있습니다. 결제 후 일부는 조리·좌석을 기다리다 전액 환불을 선택합니다. 조리 전 취소분은 재고를 복원하며, 조리 후 취소분은 재료를 소비한 상태로 한 번만 비용에 반영합니다.
5. 실제 대기·환불·조리 후 식재료 손실·방문 포기·저예산 및 대기 민감 고객의 제공률을 기록합니다. P90·P95 대기는 식사가 제공된 고객 기준입니다. 미구매와 방문 포기는 평가식에서 0이며, 이는 평가식의 정의입니다.

재방문은 같은 7일 또는 14일 운영기간 안에서 이어집니다. 다른 운영기간에는 고객 기억과 재고를 다시 초기화합니다. 추천군과 대조군에는 같은 잠재 고객과 외부 난수를 주고, 실제 방문과 주문·재고·대기열은 별도로 진행합니다.

## 결과를 해석하는 법

| 비교 | 확인하려는 효과 |
|---|---|
| 무작위 추천 − 미추천 | 무작위 메뉴를 표시하는 추천 화면을 도입한 효과 |
| 인기 추천 − 미추천 | 같은 화면에 사전 인기 메뉴를 표시한 효과 |
| PPO − 미추천 | 학습 추천 기능을 도입한 전체 효과 |
| PPO − 무작위/인기 추천 | 동일한 카드 반응 규칙에서 메뉴 선정 방식이 만든 차이 |

각 비교는 **동일 평가함수 안에서** 수행합니다. 평가함수별 PPO와 LHS는 유지합니다. 고객·가게 점수와 Δ의 부호를 보존하고, 양수 기준점수에서만 일반 향상률을 계산합니다. 시설을 독립 단위로 삼아 여러 고객 구성과 반복 수요를 독립 시설처럼 세지 않습니다.

`paired_test.json`에는 시설·고객 구성·메뉴/매장 변경별 일별 결과와 비교군을, `summary.json`에는 구성별 결과와 비교군 차이를 저장합니다. 대시보드는 최종 비교군과 구성별 Δ를 함께 보여줍니다. `config/adaptive_realism_smoke.yaml`은 실행 점검용입니다.

## 현장 검증이 필요한 부분

동행자의 공동 주문·좌석 점유, 실제 고객의 탐색·인내시간 계수, 장기간 재방문, 미관측 행동 유형, 현장 추가 학습 속도는 이번 구현의 검증 범위 밖입니다. 실제 익명 주문·노출·품절·대기 기록을 확보하면 먼저 미추천 모형을 보정하고, 다른 날짜와 시설에서 검증해야 합니다. 합성 실험의 개선폭을 현장 효용으로 해석하지 않습니다.

입력은 49개 특성으로 변경되었고 실행 기록 스키마도 바뀌었습니다. 새 실험 ID를 사용합니다. 기존 47개 입력 모델과 이전 실험 폴더에 이어 쓰지 않습니다.

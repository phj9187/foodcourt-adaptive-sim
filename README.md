기존 CEM과 별개인 PPO Actor–Critic 프로젝트입니다. **평가함수마다 공통 AI 하나를 여러 푸드코트에서 학습하고, 같은 평가함수로 AI 개입·미개입의 차이를 측정**합니다. 실제 만족도와 평가함수의 일치는 향후 사람의 반응으로 검증합니다.

## 2026-11-07 고객 행동·효용 검증 수정

**한 푸드코트 안에서 서로 다른 고객이 섞여 여러 날 방문**합니다. 일부 고객은 같은 기본 특성을 유지하며 다시 방문하고, 일별 취향 변화와 지난 경험이 반영됩니다. 여기에 고객 구성 비중이 다른 환경들을 반복해 같은 AI를 학습합니다. 메뉴 수가 많으면 반드시 만족도가 낮아진다는 벌점은 없습니다.

- 예산·가격 민감도, 시간 여유·대기 민감도·인내시간을 연결한 합성 공동분포와 오차가 있는 5단계 입력을 사용합니다.
- 비교 후 선택·적당히 만족하면 탐색 종료·가격/시간/취향 우선 선택이 매일 혼합됩니다. 세 기본 환경은 특정 방식의 비중이 60%, 나머지가 각각 20%인 민감도 가정입니다. 실측 비중이 아닙니다.
- 추천 카드는 고려 후보에 들어갈 수 있으며 선택을 강제하지 않습니다. **미추천·같은 화면의 무작위 추천·사전 인기 추천·PPO 추천**을 비교합니다. 사전 인기는 합성 공개 신호이며 PPO에도 같은 신호를 제공합니다.
- 방문 포기·줄 진입 포기·대기 중 이탈·결제 후 조리/좌석 대기 취소를 기록합니다. 조리 전 취소는 재료를 반환하고, 조리 후 취소는 이미 사용한 식재료비를 한 번만 비용에 반영합니다. 전액 환불 가정입니다.
- 기본 `exogenous` 수요는 설정의 인원 기준에 시설별 독립 합성 인구 배율을 곱합니다. 조리능력에 수요가 자동으로 맞춰지지 않습니다. 고객 예산은 시설 생성 때 고정해 가격 개입 후 함께 올라가지 않게 했습니다. 실제 수요·예산 자료로 보정된 것은 아닙니다.
- 양쪽의 **잠재 방문 기회**를 맞추고, 경험에 따라 실제 방문 수가 달라지는 것은 허용합니다. 반복 고객 상태는 같은 시설 운영기간 안에서 유지하고 다른 운영기간에는 초기화합니다.
- 대시보드에 고객 구성별 Δ와 무작위·인기 추천 대비 AI 차이를 추가했습니다. 자세한 반영 범위와 한계는 [수정 기록](docs/realism_implementation_20261107.md)을 확인하세요.

현재는 27개 운영 범위와 3개 구조 좌표를 포함한 30차원 입력 설계를 사용합니다. 기본 파일럿은 일평균 잠재 방문 기회 35명을 기준으로 시설별 독립 배율을 적용합니다.

## 2026-11-06 연구자료 반영

사용자가 제공한 `푸드코트_생성_연구자료_통합본_20261105.txt` 및 보존 원장 `venue_evidence.json`을 반영했습니다. 원장은 공개 출처의 과거 확인 기록이지 이번에 모든 링크를 새로 확인한 결과가 아닙니다. 자료의 과거 CEM·가중치 출력·32모델 구상은 실행 지시로 적용하지 않았습니다. 현재의 **메뉴 직접 추천·평가함수별 공통 모델**을 유지합니다.

- **기본 대상은 대학 푸드코트**입니다. 다른 유형은 `config/adaptive_multitype.yaml`에서 대학·쇼핑몰·휴게소·공항·레저를 별도 균등 배정하는 탐색 실험으로 선택합니다. 균등 배정은 현실의 시장 비중이 아닙니다.
- **매장·좌석·영업시간 등 같은 공간에서 확인한 조합을 유지**합니다. 인제대 두 층은 별도 사례입니다. 상업시설 전체 점포 수를 푸드코트 매장 수로 사용하지 않으며 계획 사례는 제외합니다.
- 직접 사례를 우선 포함하고 추가 표본은 **같은 유형의 사례 쌍에서 하나의 보간계수**로 매장 수와 좌석 수를 함께 생성합니다. 빠진 필드는 공학적 가정 또는 용량 기반 계산이라고 각각 표시합니다.
- 운영 조건은 유형별 **최소 거리 기준으로 선택한 24개 후보 중 하나의 LHS 설계**로 생성합니다. 자료의 27개 민감도 범위를 운영에 연결하고 구조 좌표 3개를 더합니다. 재방문·기억도 합성 민감도 가정입니다. 과거 연구의 실제 출력 공간 4개 후보 재선택 단계까지 그대로 복원한 것은 아닙니다.
- 메뉴는 모두 가상 변형입니다. 공개된 이름·일부 가격만 참고하며 맛·레시피·원가·조리시간·알레르기는 합성 가정입니다. 한식·동남아식 모형 분류를 추가해 일부 잘못된 이전 태그를 수정했습니다. 음료·디저트·뷔페·단체예약을 재현하지는 않습니다.

## 무엇이 운영에 연결되는가

| 조건 | 연결 방식 |
|---|---|
| 매장별 조리 자원·메뉴 수·불균형 | 매장마다 다른 정수 자원·메뉴 후보 생성 |
| 조리시간·가동 부하 | 잠재 수요 = 합성 처리능력 × staff_load |
| 미확인 키오스크 수 | 잠재 수요·기본 주문시간·목표 부하로 계산, 확인된 대수 우선 |
| 가격 배율·원가 계수 | 원화 기준 가상 메뉴 가격·식재료 단위원가 생성 |
| 주문시간·좌석 체류시간 | 주문 탐색·결제·좌석 해제 이벤트에 적용 |
| 수용·인내·탐색 수·취향 오차 | 고객의 추천 수용·이탈·탐색에 적용 |
| 수요 변동·첨두 비중·주말 배율 | 일별 인원과 유형별 첨두/비첨두 혼합에 적용 |
| 영업 요일·시간 | 휴무일 고객 미투입, 현재 운영시간에 주문 접수 |
| 재료 수명·초기 충당 일수 | 매장·재료별 재고 묶음의 만료와 초기 수량에 적용 |
| 검토 주기·리드타임·안전 여유·지연 확률 | 관측 소비와 초기 용량 추정에 기반한 발주·입고에 적용 |

기본 `demand_mode: exogenous`에서는 `visitors × 시설별 독립 배율 × demand_scale`을 잠재 방문 기회의 일평균으로 사용합니다. 배율은 평균 1, 로그 표준편차 0.5인 합성 로그정규분포이며 LHS 좌표와 별도입니다. `fixed`는 모든 시설에서 `visitors`를 사용하고, 선택 설정 `capacity`는 시설별 처리능력 × 가동 부하 × `demand_scale`을 사용합니다. 세 모드 모두 일별 변동과 영업 달력이 적용됩니다. 어느 모드도 실측 수요라고 주장하지 않습니다.

## 재고와 달력

남은 재고의 35%를 일률적으로 폐기하거나 매일 고정 비율로 즉시 보충하지 않습니다. **재고 묶음별 만료·선입 만료 우선 소비(FEFO)·배송 중 물량·기본 납품 지연·추가 지연**을 관리합니다. 미래 실제 손님 수를 사용하지 않습니다. AI에는 주문 당시 예상 납품일을 알려주며 미래의 무작위 지연 결과를 미리 보여주지 않습니다.

재료 수명은 상업시설의 실측 소비기한이나 안전 기준이 아닌 연구 가정입니다. 만료·입고는 정수 달력일의 영업 시작 시 처리합니다. **주문·좌석 대기열은 당일 영업을 마친 뒤 정리하므로, 자정 너머 대기열을 이어가는 진정한 24시간 연속 모형은 아닙니다.** 재고·발주·반복 고객 경험은 한 연속 운영기간 안에서 유지되며, 다른 학습 운영기간을 시작하면 새 에피소드입니다.

수량과 금액의 보존을 검사하고 기말 재고·배송 중 물량도 기록합니다. 기말 재고 가치가 미래 판매를 보장하지 않으며, 기간 밖 만료 위험은 최종 보상에 완전히 포함되지 않습니다. 발주 규칙 자체를 PPO가 학습하는 것은 아닙니다.

## AI와 평가함수

고객 입력·메뉴 특성·매장 상태·시설 규모와 영업 정보·요일·관측 가능한 공급 상태를 입력합니다. 예산·알레르기·명시적 제외 조건·재고로 후보를 걸러내고, 같은 신경망으로 후보 메뉴들을 처리해 메뉴를 직접 추천합니다. 크리틱은 운영기간의 누적보상을 예측합니다. 사용자가 반드시 추천을 따르지는 않습니다.

```
C = a*T^p + b*P^p + c*W^p                    (a+b+c=1)
S = q*(환불 차감 매출-사용 식재료비)/(N*6000) - (1-q)*재고 만료 폐기비용/(N*6000)
F = λ*C + (1-λ)*S
ΔF = F(AI 개입 결과) - F(AI 미개입 결과)
```

T·P·W는 미구매·방문 포기를 0으로 포함한 하루 잠재 방문 기회 평균, N은 잠재 방문 기회 수(최소 1)입니다. `visitors`는 호환성상 이 분모를 뜻하며 실제 방문 수는 `actual_visitors`에 따로 기록합니다. 사용 식재료비에는 조리 후 취소분이 포함되며 같은 비용을 만료 폐기비용에 또 더하지 않습니다. 지수 p는 평균 후 적용합니다. 가게 지표는 기회당 6,000원으로 정규화합니다. 인건비·임차료 등을 뺀 순이익이 아닙니다.

평가함수의 LHS는 첫 세 좌표를 음의 로그 변환 후 합 1로 만들어 a·b·c를 얻고 나머지를 λ·q에 사용합니다. 변환 후 개별 계수까지 LHS 간격이 유지되지는 않습니다. 경계 후보 3개와 지수 0.5·1·2도 비교할 수 있습니다. 정해둔 함수족의 탐색이지 모든 주관적 평가함수의 포괄이 아닙니다.

운영기간을 수집한 뒤 PPO를 갱신합니다. 하루 F를 그날 마지막 추천에 부여하고 이후의 F를 합친 Monte Carlo 반환값을 사용합니다(할인율 1, GAE 미사용). 평가함수 계수를 바꾸어도 고객 행동 모형은 바꾸지 않습니다.

## 학습·검증·시험

- 매장별 물리적 상태를 분리하고 여러 시설의 학습 경험을 같은 모델에 모읍니다. 평가함수·독립 초기화 반복마다 모델을 따로 둡니다.
- 학습·검증·최종 시험의 **합성 시설과 고객 난수는 분리**합니다. 다만 공개 근거 사례는 공유하므로 시설 원출처까지 배제한 시험은 아닙니다.
- 검증의 도입 효과로 모델을 선택하고 최종 시험은 선택·학습에 쓰지 않습니다. 시험은 고정 모델의 일반화 및 메뉴·매장 구성 변화 대응입니다. 현장 추가 학습 속도 시험은 아직 없습니다.
- 양쪽에 같은 잠재 고객·도착·선택 잡음·조리 잡음·달력을 적용하고 정책 때문에 달라지는 재고·대기열은 각각 진행합니다.
- 모든 평가함수는 같은 환경 설계를 사용합니다. 점수의 정의가 다른 모델끼리 자기 점수 숫자로 순위를 만들지 않습니다.
- 독립 단위는 푸드코트입니다. 같은 시설의 여러 날과 반복 수요를 독립 표본 수로 부풀리지 않습니다.

## 저장과 호환성

운영기간 하나와 PPO 갱신을 마칠 때마다 모델·최적화·난수·진도를 원자적으로 저장하고 직전 체크포인트도 남깁니다. 중단 시 미완료 운영기간은 다시 계산합니다. 동일 소스·설정·주요 라이브러리 버전에서 같은 폴더로 재시작합니다. Drive 쓰기 완료가 별도 장치 백업이나 업로드 완료를 보장하지는 않습니다. Colab 자동 재접속과 임의 12시간 종료 제한은 없습니다.

이번 생성기·입력 차원·재고 모형이 달라졌으므로 **이전 모델이나 실험 폴더에 이어 쓰지 않고 새 실험 ID로 실행**합니다. 이전 결과는 보존하지만 새 조건의 검증 결과로 재사용하지 않습니다.

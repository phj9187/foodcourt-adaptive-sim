# 가변 푸드코트 추천 시뮬레이션

[Colab에서 열기](https://colab.research.google.com/github/phj9187/foodcourt-adaptive-sim/blob/ad481f13d9acd9d5aa2e0157434fbcbb9314f962/notebooks/foodcourt_adaptive_colab.ipynb) · [실행 검증 기록](docs/validation_20261105.md)

기존 `koisk-simulation`과 별개의 독립 프로젝트입니다. 기존 실행 코드·실험 결과를 불러오지 않습니다. 공개 대학 메뉴 자료의 이름·가격·구성 근거만 출처와 함께 복사해 사용했습니다.

목표는 **평가함수를 지금 하나로 결정하는 것**이 아니라, 여러 평가함수로 각각 학습한 AI가 **그 함수의 기준에서 AI 미개입보다 얼마나 개선하는지** 파악하는 것입니다. 실제 주관적 만족도와의 관계는 향후 사람의 반응으로 검증해야 합니다.

## 구성

1. 공개 자료 기반 매장 후보에서 2~6개 매장, 매장별 3~10개 메뉴를 조합합니다. 최소 두 종류의 업종, 공유 키오스크와 좌석, 매장별 조리 인력을 둡니다. **이 수치 범위와 조합 확률은 실측 분포가 아닌 연구 가정**입니다.
2. 고객은 취향·가격 민감도·대기 민감도를 5단계로 입력합니다. 예산, 알레르기 및 제외 업종도 반영합니다. 고객의 숨은 선택 잡음과 사후 결과는 신경망 입력에서 제외합니다.
3. 예산·알레르기·명시적인 제외 조건·재고로 메뉴를 걸러낸 다음, 신경망이 메뉴를 직접 추천합니다. 사용자가 반드시 추천을 따르도록 만들지 않습니다.
4. 같은 신경망으로 모든 후보 메뉴를 처리하고 후보 집합을 요약하므로, 메뉴 수와 순서에 고정된 출력층이 없습니다.
5. **PPO Actor–Critic**으로 학습합니다. 액터는 메뉴 선택 확률, 크리틱은 남은 운영기간의 누적보상을 예측합니다. 추천 가중치 식과 CEM은 사용하지 않습니다.
6. 각 푸드코트를 여러 날 연속 운영합니다. 매일 남은 재고의 35%를 폐기하고 나머지를 이월합니다. 다음 날 목표 재고까지 보충하되 하루 보충량은 목표의 60%로 제한해, 전날의 재고 부족이 다음 날에도 영향을 줄 수 있습니다. 고객 대기열은 당일 처리 후 종료합니다.
7. 여러 푸드코트를 주기적으로 다시 방문하며 학습하고, 별도 푸드코트로 검증·시험합니다. 시험에는 메뉴 삭제·추가 및 한 매장 영업 개시가 있는 조건도 포함합니다. 매장 폐점·레시피 교체 등 모든 변경을 구현한 것은 아닙니다.

## 평가함수 샘플링

방문자 전체를 분모로 취향 적합도 `T`, 예산 대비 가격 여유 `P`, 대기 효용 `W`를 계산합니다. 미구매자의 세 값은 0입니다. 가격·시간과 만족의 관계는 합성 고객 가정입니다.

```
C = a*T^p + b*P^p + c*W^p            (a+b+c=1)
S = q*매출총기여 - (1-q)*폐기비용
F = λ*C + (1-λ)*S
```

가게 지표는 방문자당 6,000원으로 나누어 정규화합니다. `매출총기여=매출-판매분 식재료비`이며 폐기비용을 중복 차감하지 않습니다. 임대료·인건비 등 고정비는 포함하지 않습니다. `p`는 일별 방문자 평균 구성요소에 적용합니다. 개인별 효용의 지수 변환 후 평균과는 다릅니다.

LHS는 5차원 단위공간을 층화합니다. 첫 세 차원을 지수 변환·정규화해 `(a,b,c)`로 만들고 나머지는 `(λ,q)`로 사용합니다. **변환 후 개별 가중치까지 LHS 층화가 유지된다는 뜻은 아닙니다.** 내부 샘플 외에 고객만·판매기여만·폐기감소만 보는 경계 후보를 추가합니다. `p=0.5,1,2`도 비교할 수 있습니다. 이 함수족이 모든 가능한 주관을 포괄하지는 않습니다.

평가함수별·독립 초기화 반복별로 별도 모델을 만듭니다. 다른 평가함수 사이의 점수를 순위로 만들지 않습니다. 같은 함수로 AI 개입·미개입을 평가해 차이를 저장합니다.

```
ΔF = F(AI 개입 결과) - F(AI 미개입 결과)
```

같은 고객·도착·외부 선택 잡음·조리시간 잡음을 두 조건에 사용하고, 추천으로 달라지는 구매·재고·대기열은 독립 진행합니다. 각 조건의 재고 이력도 따로 유지합니다. 고객점수 향상 `ΔC`와 이익 변화도 함께 저장합니다. 점수가 0 또는 음수가 될 수 있어 향상률을 일률적인 백분율로 표현하지 않습니다.

## 학습과 평가의 경계

- 고객 반응 모형은 평가함수 계수를 바꾸어도 동일합니다. 보상 기준을 바꾸었다고 고객의 숨은 취향을 바꾸지 않습니다.
- PPO는 여러 날 운영 기록을 수집한 뒤 갱신합니다. 각 날 종료 시 그날의 `F`를 마지막 추천 행동에 부여하고, 같은 운영기간의 이후 보상을 모두 합친 반환값으로 학습합니다. 할인율은 1, 크리틱 목표는 Monte Carlo 반환값입니다. GAE를 사용한 구현은 아닙니다.
- **훈련 종료 모델 중 검증용 푸드코트에서 도입 효과가 가장 큰 모델**을 선택합니다. 시험 결과로 선택하지 않습니다.
- 현재 최종 시험은 **고정된 모델의 일반화·구성 변화 대응**입니다. 새 현장에서 추가 학습하며 얼마나 빨리 회복하는지 측정하는 별도 프로토콜은 아직 포함하지 않았습니다.
- 같은 푸드코트의 날짜·수요 반복을 독립 표본으로 세지 않습니다. 푸드코트별 평균 차이와 그 분산을 저장합니다. 독립 학습 반복도 각각 보관합니다.

## 로컬 실행

Python 3.11 이상에서:

```bash
python -m pip install -e .
python -m unittest discover -s tests -v
python -m kiosk_adaptive.study --config config/adaptive_pilot.yaml --output outputs/my_pilot
```

`config/adaptive_pilot.yaml`은 5개 평가함수×1회 독립 학습의 작은 검증 설정입니다. 연구용 예시 `config/adaptive_colab.yaml`은 `(LHS 24 + 경계 3) × 지수 3 × 반복 3 = 243개 모델`입니다. 먼저 작은 실행으로 시간과 결과를 점검하세요. 이 설정이 충분한 학습량이라는 보장은 없습니다.

## 저장과 재시작

푸드코트 한 곳의 연속 운영기간을 마치고 PPO 갱신할 때마다 모델·최적화 상태·난수 상태·진도를 원자적 교체로 저장합니다. 바로 전 체크포인트도 별도 보관합니다. 같은 명령과 출력 폴더로 재실행하면 완료한 운영기간 다음부터 이어갑니다. 현재/직전 체크포인트까지 모두 손상된 경우에는 자동 복구하지 않습니다.

중단 시 마지막 미완료 운영기간의 기록은 다시 계산합니다. 소스·설정·주요 라이브러리 버전이 달라지면 같은 실험 폴더에 이어 쓰기를 거부합니다. Colab에서는 Drive에 직접 저장하지만, 파일 교체와 직전 사본은 별도 장치의 백업이나 Drive 업로드 완료 보장을 뜻하지 않습니다. Colab 연결이 끊어진 뒤 자동 재접속하는 기능은 없습니다.

출력: `manifest.json`, `court_catalog.json`, 모델별 `checkpoint.pt`·`checkpoint.previous.pt`·`progress.json`·`paired_test.json`·`learning_history.json`, 전체 `summary.json`·`comparison.csv`.

## 근거와 한계
